# Conventions (for agents implementing components)

Ledger UI: Phoenix LiveView components styled only with Tailwind CSS v4 utilities (theme: `assets/css/ledger_ui.css`, generated by `scripts/tw/tw_theme.py`; no component CSS, no `lu-*` classes). Read `MIGRATION.md` for the rules.
Design data lives in the private repo `devaction-labs/ledger_ui_design` (read-only here; see "Design data and tooling"). Read this file fully before touching code.

## Layout

| Path | What |
|---|---|
| `lib/ledger_ui/components/<api>.ex` | One module per API module of `$LEDGER_DESIGN/system/PARIDADE.md` (`context_menu` -> `LedgerUI.Components.ContextMenu`). All 109 stubs already exist and are already listed in `LedgerUI.Components.__modules__/0`. |
| `test/ledger_ui/components/<api>_test.exs` | Your tests. |
| `ledger_ui_design/showcase/examples/<id>/NN.heex` | Your showcase examples + parity: in the private repo (see "Showcase, parity and publishing"). |
| `priv/static/ledger_ui/hooks/<name>.js` | Client hook, only if JS commands cannot do the job. |
| `$LEDGER_DESIGN/canvas/G*Claro*.dc.html` | **Markup source of truth**: the design canvas. When it differs from the vitrine, the canvas wins. |
| `$LEDGER_DESIGN/vitrine/sec/<id>.json` | Fallback markup (`h` = HTML to reproduce, `t` = title) for sections the canvas does not have. |
| `$LEDGER_DESIGN/system/components/<Name>/README.md` | **API source of truth** (function names, attrs, defaults, values, slots). |

Do NOT edit files owned by others: `lib/ledger_ui/components.ex`, `lib/ledger_ui.ex`, `component.ex`, `helpers.ex`,
`components/icon.ex`, `mix.exs`, `priv/static/ledger_ui.esm.js`, `priv/static/ledger.{css,js}`, the showcase app code
(`showcase/lib`, `showcase/test`, `showcase/mix.exs`, in `ledger_ui_design`). If a shared change is needed, say so in your final report.
Edit only your own module file(s), your tests, your example folders (in `ledger_ui_design`) and your hook files.
Function names must be unique across modules (all are imported by `use LedgerUI`); if two API READMEs
define the same function name, report it.

## Filling a stub

```elixir
defmodule LedgerUI.Components.Badge do
  @moduledoc """
  Short description, then usage example.
  """
  use LedgerUI.Component          # Phoenix.Component (+ keep- global prefix), JS alias, cx/1, <.icon>

  @styles %{
    "base" => "lu-badge",
    "variant" => %{"soft" => nil, "solid" => "solid", "outline" => "outline"},
    "tone" => %{"neutral" => nil, "success" => "pos", "error" => "neg"},
    "size" => %{"sm" => "sm", "md" => nil}
  }

  attr :variant, :string, default: "soft", values: ~w(soft solid outline)
  attr :tone, :string, default: "neutral", values: ~w(neutral success error)
  attr :size, :string, default: "md", values: ~w(sm md)
  attr :class, :any, default: nil
  attr :rest, :global
  slot :inner_block, required: true

  def badge(assigns) do
    # Form 1 (default): a pure function called from the template with the assigns as arguments.
    ~H"""
    <span data-part="badge" class={[badge_class(@variant, @tone, @size), @class]} {@rest}>
      {render_slot(@inner_block)}
    </span>
    """
  end

  # In a function body `@styles` is the module attribute (compile-time, O(1) lookups); inside
  # `~H` `@x` is an assign. Keep the lookups in a function and call it from the template.
  defp badge_class(variant, tone, size) do
    cx([@styles["base"], @styles["variant"][variant], @styles["tone"][tone], @styles["size"][size]])
  end
end
```

### Derived values: two forms

A value computed from the attrs (classes, a label, a data attribute) can be handed to the template in two ways. Both give the same HTML;
they differ in what LiveView sends again. See rule 4 of `guides/liveview-eficiente.md` (measured on a badge: swapping the slot sends 171 B
with a plain `assign/3`, 21 B with either form below).

1. **Pure expression in the template (default).** Call a function with the assigns as arguments:
   `class={[badge_class(@variant, @tone, @size), @class]}`. LiveView evaluates it again only when one of the cited `@x` changes, and the
   sources are the arguments, so there is no "forgot a source and the value went stale". Public API only. Use it when the value is used once
   or twice. New components and the ones being refactored use this form.
2. **`assign/3` + `settle/3`.** Use it when the value feeds several places of the template or is passed on to a child, or when it also reads
   something outside the assigns (locale, `Application.get_env/2`; then leave it out of the `settle/3` list or add the `:locale` attr):

   ```elixir
   changed0 = assigns.__changed__
   assigns = assign(assigns, :cls, cls(assigns.variant, assigns.size))
   assigns = settle(assigns, changed0, cls: [:variant, :size])
   ```

   (`changed0` is the `__changed__` the component received, read before the first `assign/3`; see `LedgerUI.Helpers.settle/3`.)

   A bare `assign(assigns, :cls, ...)` is wrong here: the key is always "changed", so the value is sent again on every call (a new label, a
   new body). `settle/3` takes it back out of `__changed__` when no source changed. List every attr the value reads, directly or in a helper.
   Every new `settle/3` call gets a `LedgerUI.DiffCase.each_source/3` test with all of its sources (`test/ledger_ui/change_tracking_test.exs`).

`settle/3` and `LedgerUI.I18n.track/2` write to `assigns.__changed__`, and `LedgerUI.Helpers.render_slot_full/2` calls
`Phoenix.Component.__render_slot__/3`. Neither is public API of Phoenix LiveView. `test/ledger_ui/lv_internals_canary_test.exs` fails with
an explicit message when the shape of `__changed__` or that function changes, and the scheduled job `.github/workflows/lv-main.yml` runs the
suite against the `main` branch of LiveView every week. Outside `helpers.ex`, do not call `Phoenix.Component.__render_slot__/3` directly.

Rules:

- Attribute style: `attr :variant, :string, default: "canvas", values: ~w(...)`, `attr :rest, :global`,
  `attr :class, :any, default: nil` merged last with `cx/1`. Names, defaults, values, slots follow the component README exactly.
- `cx/1` only joins strings, drops `nil`/`false`/empty, accepts `{class, bool}` tuples. No class merging/Tailwind.
- Markup must reproduce the `lu-*` classes and structure of `$LEDGER_DESIGN/vitrine/sec/<id>.json` previews exactly
  (tag, classes as a set, attributes, text, order). `data-part="<part>"` on roots/parts is allowed (ignored by parity).
- Icons: `<.icon name="download" size="sm" />` (server-side; see `LedgerUI.Components.Icon`). Never `<i data-i>`: we do not rely on `LedgerUI.hydrate()` in LiveView-owned DOM.
- `use LedgerUI.Component` already sets `global_prefixes: ["keep-"]` so `keep-class`, `keep-hidden`, `keep-style`,
  `keep-data-*` flow through `:global`.
- Open/close: use `LedgerUI.open/close/toggle` (class `open` on `#id`) or `Phoenix.LiveView.JS`.

## Texts (i18n)

A visible text, `aria-label`, `title`, placeholder, `sr-only` text or empty state of a component is never a literal in the
module: it is a key of `LedgerUI.I18n` (`lib/ledger_ui/i18n/en.ex` and `pt_br.ex`, both required).

- The attr is `attr :clear_label, :string, default: nil` (what the caller gives wins) and the function starts with
  `assigns = I18n.texts(assigns, clear_label: "bulk_bar.clear")` (a text that was Portuguese before i18n: `{:pt, key}`; an attr where
  `nil` means "none": default `:default` and `I18n.texts(assigns, [label: key], :default)`).
- The component has `attr :locale, :string, default: nil` (the attr wins over the process locale, the app config and `"en"`). A private
  piece gets `locale={@locale}` from the one that calls it.
- A `data-lu-*` attribute read by a hook carries the translated text and is written only when it differs from the English one
  (`I18n.non_default/2`), so the default HTML stays the same; the hook never has a text of its own beyond the English fallback.
- Prove nothing changed: `MIX_ENV=test mix run scripts/i18n_snapshot.exs out.html scripts/i18n_snapshot_cases.exs` in two checkouts and diff.

## Performance (mandatory)

- Keep templates mostly static, so LiveView change tracking sends only the dynamic bits. Do not wrap large static markup in conditionals/helpers that touch assigns.
- No `Enum`/heavy computation inside `~H`. Precompute in a private function, a module attribute or at compile time, and call it from the template with the assigns as arguments (form 1 above), or use `assign/3` + `settle/3` (form 2). Never a bare `assign/3` of a derived value. Full list of rules: `guides/liveview-eficiente.md`.
- Style maps as module attributes (`@styles`), O(1) lookups; no runtime class building beyond `cx/1`.
- Open/close/toggle via `Phoenix.LiveView.JS` (no server round trip). Hooks only where JS commands cannot do it (positioning, keyboard nav, drag, canvas).
- Hooks: event delegation, clean up in `destroyed`, no polling, respect `prefers-reduced-motion`.
- Lists/tables accept `@streams` (`phx-update="stream"`, `row_id` attr).
- Client-owned DOM (charts, signature pad, editors) goes under `phx-update="ignore"` with a stable `id`.
- Stable ids: never random per render. If an id is needed and not given, require the attr or derive it deterministically.
- Use `attr ... values:`: compile-time validation, free.

## Client hooks

Do not use JS getters (`get x()`) in hook objects: LiveView copies the hook object and evaluates getters before `this.el` exists. Use methods.

A component needing a hook creates `priv/static/ledger_ui/hooks/<name>.js` with `export default { mounted() {...}, updated() {...}, destroyed() {...} }`
and puts `phx-hook="LedgerUI.<Name>"` (filename `dropdown.js` -> `"LedgerUI.Dropdown"`; `my_hook.js` -> `LedgerUI.MyHook`) with a stable `id` on the element.
**Do not edit `ledger_ui.esm.js`**: report your hook files; integration runs `elixir scripts/gen_hooks_index.exs`,
which regenerates imports and the `Hooks` map. Consumers: `import {Hooks, DOM} from "ledger_ui"` (see README).
`ledger.js` stays as the chart/runtime library (`window.LedgerUI.lineChart` etc.); wrap charts in a hook + `phx-update="ignore"`.

## What `use LedgerUI` imports

Only function components (`name/1` declared with `attr`/`slot`) and the documented JS/socket helpers listed in
`LedgerUI.Components.__imports__/1` (`show_toast/2`, `put_toast/3`, `dismiss_alert/0`...). Every other public
function of a component module is an implementation helper: mark it `@doc false`, call it by its full module name, never rely on
it being imported (`test/ledger_ui/use_imports_test.exs` fails otherwise). A new documented helper goes in the `@api` map of
`lib/ledger_ui/components.ex`.

## Accessibility

- ARIA is rendered **server-side**, in the HEEx: `role` (`dialog`, `menu`, `menuitem*`, `tablist`/`tab`/`tabpanel`,
  `tree`/`treeitem`/`group`, `combobox`/`listbox`/`option`, `tooltip`, `group`...), `aria-modal`, `aria-labelledby`,
  `aria-describedby`, `aria-haspopup`, `aria-expanded`, `aria-controls`, `aria-selected`, `aria-checked`,
  `aria-current`, `aria-busy`, `aria-label` on icon-only controls, `tabindex` (roving tabindex included), `aria-hidden`
  on decorative SVGs. The initial state must be correct in the HTML sent by the server (no JS needed to be accessible).
- Hooks only **update state** of attributes that already exist (flip `aria-expanded`/`aria-selected`/`aria-current`,
  move `tabindex`, focus management). A hook must not be the only source of an ARIA attribute.
- Hook configuration goes in `data-lu-*` attributes. `phx-*` is LiveView's reserved namespace: never invent
  `phx-lu-*` or similar.

## Tests

Attribute order of `{@rest}` and key order of the JSON in `data-lu-config` (date, datetime and time pickers, line chart) depend on the atom
table: a small map with atom keys is iterated in the order the atoms were created, not by name, and that order follows the order the
modules were loaded (#109). Two runs of the same code can print the same attributes in a different order. Inside one VM the order is stable, so
production is not affected; snapshots and parity comparisons are. Never compare raw HTML between two runs: normalize it first with
`LedgerUI.HTMLNormalizer.normalize/1` (`test/support/html_normalizer.ex`), which sorts the attributes of every tag, sorts the keys of the JSON
inside `data-lu-*` attributes and replaces the random id of `show_toast` (`toast-<digits>`) by `toast-N`.

defmodule LedgerUI.Components.BadgeTest do
